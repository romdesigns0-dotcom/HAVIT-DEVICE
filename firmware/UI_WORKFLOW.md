# UI design and preview workflow

## Current sources

- `main/main.cpp` is the runtime source for the current ESP32 interface. It builds
  native LVGL objects for onboarding, pairing, Wi-Fi settings, and the home view.
- `main/assets/` contains the image and font assets embedded in the firmware.
- `../ui/` contains the LVGL Editor project, with three earlier exported screens.
  Those XML files are useful as layout references, but they are not the source
  from which this firmware currently builds its screens.
- `build/havit_os_firmware.bin` is generated by the ESP-IDF build. It is not a
  Windows simulator executable.

## Bringing in updated Figma screens

Keep frames at the device's 360 x 360 canvas. In the LVGL Editor, import the
design and keep each meaningful part as its own object where practical: ring or
background, eyes, text, icons, and buttons. Exported XML and assets help preserve
the Figma measurements, then implement or update their native-LVGL equivalents
in `main/main.cpp` and replace the matching firmware assets in `main/assets/`.
Do not replace the firmware's pairing or Wi-Fi event handlers when only changing
the visual layout.

The LVGL Editor preview can show imported XML layouts. For an interactive preview
of this ESP32 firmware on a PC, use a desktop LVGL build for the 360 x 360 display;
the ESP-IDF Xtensa firmware build itself only produces code for the ESP32-S3.
No desktop toolchain or simulator executable is currently included in this repo.

## Intro animation

The first firmware screen draws the two eyes as separate rounded LVGL objects and
animates their vertical scale, so no full-screen frame sequence is needed. The
intro can blink on a loop while startup data loads; on readiness, switch to the
main view and let LVGL remove the intro screen. Keep any static Figma frame export
as a reference, not as an animation whose entire 360 x 360 bitmap is redrawn each
frame.

The current firmware source contains this repeated eye-blink animation. It has
been built successfully for the ESP32-S3; it has not yet been flashed or observed
on the physical watch.

The four intro frames shown in the design reference are not yet four navigation
states in the firmware. The current firmware displays one welcome view before
Continue, so turning those frames into a timed onboarding sequence also requires
defining the loading-complete condition and its relationship to the Continue
button.

## Storage

The current build targets a board configured with 16 MB flash and Octal PSRAM.
The partition table reserves a 3 MB firmware app partition. This firmware build
is about 2.90 MiB, with about 108 KiB (3%) left in the smallest app partition.
Normal screens, embedded graphics, and LVGL objects do not require an SD card,
but the app partition is close to full. Before adding the new screens and assets,
measure the rebuilt image and consider expanding the app partition within the
available 16 MB flash. Consider an SD card only for a large or changeable
collection of files beyond practical flash capacity. The current firmware
partition table and UI do not configure an SD card.
